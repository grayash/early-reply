# 먼저 온 답장

한두 줄 글을 쓰면, 오래전에 누군가 실제로 남긴 문장 하나가 답글로 달리는 사이트.

- 문장 1,000개, 작가 222명. 전부 공개 원문 자료와 글자 단위로 대조했고 문장마다 원문 링크가 붙어 있다.
- 원문은 저작권이 끝난 글만 썼고(가장 늦게 세상을 떠난 작가 1947년), 한국어 번역은 새로 했다.
- 글은 이름 없이 공개된다. 저장하는 것은 쓴 글과 받은 답글뿐이다.

## 폴더

| 위치 | 내용 |
|---|---|
| `data/authors.txt`, `data/quotes/*.txt` | 문장 원고. 여기를 고친다 |
| `data/verified.json` | 원문 대조 결과(문장 id → 원문 링크) |
| `functions/_data/quotes.js` | 원고에서 만들어지는 파일. 직접 고치지 않는다 |
| `functions/_lib` | 답글 고르기(`match.js`), 낱말 사전(`lexicon.js`), 거르기(`filter.js`), 의미 검색(`emb.js`) |
| `functions/api` | 글 쓰기·피드·공감·신고·순위 |
| `public` | 화면(피드, 쓰기와 답장 연출, 순위, 사람, 소개) |
| `scripts` | 원고 → 데이터 만들기, 원문 대조, 시험 |

## 자주 쓰는 명령

```
npm run build     # 원고 → functions/_data/quotes.js (분류별 개수와 오류를 보여 준다)
npm run verify    # 원문 대조 (../corpus 에 원문 자료가 있어야 한다)
npm test          # 일상 글 50개로 답글 고르기 시험 (AI 없이)
```

문장을 고치거나 더한 뒤에는 `verify` → `build` 순서로 돌린다.
같은 작가의 문장은 15개까지, 판본마다 낱말이 다른 자리는 `~` 로 끊어 적는다.

## 답글 고르는 순서

1. 위기 글("죽고 싶다" 등)은 답글 없이 상담 안내만 보여 주고 저장하지 않는다.
2. 욕설·개인정보·광고는 올리기 전에 막는다.
3. 글에서 감정과 주제를 찾고, 문장마다 점수를 매긴다(꼬리표 + 낱말 겹침 + 의미 유사도).
4. 1위가 뚜렷하면 그 문장, 비슷하면 감정·주제가 둘 다 맞고 최근에 안 나온 문장, 모호하면 감정별 범용 문장.
5. AI가 연결돼 있으면 후보 여섯 개 가운데 하나를 고르고 '왜 이 문장인지' 한 줄을 쓴다. 한도를 넘거나 실패하면 한 줄 없이 간다.

## 배포 (Cloudflare Pages)

1. Cloudflare 대시보드에서 이 저장소를 Pages 프로젝트로 연결한다. 빌드 명령 없음, 출력 폴더 `public`.
2. D1 데이터베이스 `old-replies` 를 만들고, 그 id를 `wrangler.toml` 의 `database_id` 에 넣는다.
3. `schema.sql` 을 D1 콘솔에 붙여 넣어 실행한다.
4. Pages 설정의 Bindings에 D1(`DB`)과 Workers AI(`AI`)를 연결한다.
5. 환경 변수(비밀 값)로 `ADMIN_KEY`, `SALT` 를 아무 긴 문자열로 넣는다.
6. 배포 뒤 `/admin` 화면에서 `ADMIN_KEY` 를 넣고 '의미값 만들기'를 끝까지 누른다(문장 100개씩 10번).
   문장을 고쳐 다시 배포하면 이 단계를 다시 한다. 하지 않아도 낱말 방식으로 답글은 달린다.

## 배포 전에 확인할 것

- Workers AI와 D1의 무료 한도. 글 한 개에 의미값 계산 1회와 글 생성 1회를 쓴다.
- 실제 글로 `match.js` 의 `TUNE` 값(의미 유사도 비중) 조정.
- 순위는 하루 글이 `RANK_MIN`(기본 5)개를 넘어야 보인다.
